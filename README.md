# LoRAによる回答形式の学習と学習率の比較

第2回講義・基礎課題の実験記録

> **主な結果：** 学習率を `2e-4` から `1e-4` に半分にしても、今回の評価21問では形式遵守率・内容正解率は同じだった。一方、最終記録lossは `0.013810` から `0.032728` に増加した。

## 1．概要

講座で配布された `lora_format_tuning.ipynb` を使用し、架空の講座FAQを題材に、小さな指示チューニング済みモデルへLoRAによる追加学習を行った。

取り組んだレベルは **基礎** である。`CONFIG` の学習率 `lr` のみを変更し、元の設定と変更後の設定について、以下の4項目を比較した。

- 形式遵守率：`format_rate`
- 内容正解率：`content_rate`
- 最終loss
- 学習時間

出力形式は、`answer` と `needs_review` を含むJSONである。形式への遵守と、回答内容・根拠不足への対応を分けて確認した。

## 2．実験条件

### 変更した設定

学習率を `2e-4`（0.0002）から `1e-4`（0.0001）へ変更した。学習率以外の設定と、講座の学習・評価データは変更しなかった。

| 設定項目 | 元の設定 | 変更後の設定 |
|---|---|---|
| **学習率 `lr`** | **`2e-4`** | **`1e-4`** |
| モデル | `Qwen/Qwen3.5-0.8B` | 同左 |
| 学習方法 | LoRA（量子化なし） | 同左 |
| `lora_r` | 16 | 16 |
| `lora_alpha` | 32 | 32 |
| `num_train_epochs` | 20 | 20 |
| `warmup_steps` | 6 | 6 |
| `seed` | 42 | 42 |
| `max_seq_len` | 512 | 512 |
| `max_new_tokens` | 96 | 96 |
| 評価時の `do_sample` | `False` | `False` |
| 実行環境 | Google Colab・T4 | 同左 |

### 評価条件

- 各条件を1回ずつ実行した。
- 講座の評価質問21問に対する結果を比較した。
- 両条件とも40ステップ、20エポックで学習を終了した。
- FAQにない質問に対する追加の知識確認も参照した。

## 3．結果

### 学習前後と2条件の比較

| 評価項目 | 元の設定：`lr = 2e-4` | 変更後：`lr = 1e-4` |
|---|---:|---:|
| 学習前の形式遵守率 `format_rate` | 9.5%（2/21） | 9.5%（2/21） |
| 学習前の内容正解率 `content_rate` | 0%（0/21） | 0%（0/21） |
| **学習後の形式遵守率 `format_rate`** | **100%（21/21）** | **100%（21/21）** |
| **学習後の内容正解率 `content_rate`** | **90.5%（19/21）** | **90.5%（19/21）** |
| **最終loss** | **0.013810** | **0.032728** |
| **学習時間** | **227秒（3分47秒）** | **231秒（3分51秒）** |

### 記録した指標の扱い

- **最終loss**：両条件とも、学習ログの最終行（Step 40）に表示された「Training Loss」を採用した。
- **学習時間**：学習セルの出力に表示された「学習時間」を採用した。
- `result.json` の `before`・`after` に含まれる `seconds` は評価処理の時間であり、学習時間には用いていない。

## 4．考察

### 4.1．学習率の変更と評価結果

両条件とも、形式遵守率は学習前の9.5%から学習後の100%へ、内容正解率は学習前の0%から学習後の90.5%へ上昇した。

学習率を半分にすると、最終lossは0.013810から0.032728へ大きくなった。一方、学習後の形式遵守率と内容正解率には差がなかった。この結果から、今回の条件では、訓練時のlossの大小だけでは評価質問に対する成績の差を判断できないと考えた。

学習時間は227秒から231秒となり、差は4秒だった。各条件1回の実行であるため、この差を学習率の変更による速度差と断定することはできない。

### 4.2．形式の遵守と根拠不足への対応

追加の知識確認では、FAQにない締切の質問に対して、学習後も具体的な日付を回答し、`needs_review` を `false` とする例が残った。

このことから、JSON形式を守ることと、根拠が不足しているときに確認を求めることは、別々に評価する必要があると考えた。形式遵守率が100%になっても、根拠のない断定を完全に防げるとは限らない。

この追加の知識確認は、評価質問21問の集計結果とは区別して考察した。

### 4.3．ファインチューニングが向く場面

指定されたJSON形式、一定の文体、定型的な分類や応答など、望ましい出力を教師データで示せる場面に向いていると考える［1］。

今回も、`answer` と `needs_review` を含む形式への遵守率が学習後に上昇した。繰り返し使用する出力形式や応答のパターンを調整する用途では、ファインチューニングが有用になる可能性がある。ただし、形式と内容の両方を評価することが必要である。

### 4.4．ファインチューニング単独では向きにくい場面

頻繁に更新される情報を扱う場合や、回答の根拠となる資料を確認・提示したい場合には、外部資料を検索して参照するRAGなども検討することが適切だと考える［2］。

また、今回の結果からも、根拠のない質問に対する適切な対応が、ファインチューニングだけで常に保証されるとはいえない。用途に応じて、プロンプトで回答方針を明示する方法や、RAGで根拠を提示する方法と組み合わせ、根拠のない質問に対する評価を行う設計が考えられる。

今回の基礎課題では、プロンプトの変更やRAGとの比較実験は行っていない。これらは今後検討する案として述べた。

## 5．実験の限界

- 各条件1回の実行であり、実行ごとのばらつきは評価していない。
- 評価質問は21問であり、他の質問や設定への一般化には追加の検証が必要である。
- 評価率が同じであることから、すべての回答内容や各質問の正誤まで同一であるとは判断していない。
- 今回のlossと評価結果だけから、過学習の有無や未知の質問に対する性能差は断定していない。

## 6．講座ノートブックでの実行手順

1. 講座のColabノートブックを開き、ライブラリは指定された `PINS` の版を使用する。
2. 元の設定（`lr = 2e-4`）で、環境準備から学習・評価・結果保存まで順に実行する。
3. 元の設定の `result.json` と、学習ログの最終loss・学習時間を保存する。
4. `CONFIG` の `lr` のみを `1e-4` に変更する。
5. 「ランタイム → セッションを再起動」を行い、先頭から同じ順序で学習・評価・結果保存まで実行する。
6. 変更後の `result.json` を元の結果と区別して保管し、同じ定義の4指標を比較する。

学習が正常終了した場合は、トラブル対応用の再学習を追加する必要はない。任意の4bit量子化比較は、今回の基礎課題の比較には含めない。
